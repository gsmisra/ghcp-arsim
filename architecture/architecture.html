GHCP UI to LLM Enterprise Architecture

ARSIM static HTML UI -> Flask runtime -> QE orchestration -> semantic retrieval + embeddings -> GHCP-compatible LLM -> BDD/CSV outputs

Executive Summary

The browser UI does not call the LLM directly. It calls local API endpoints exposed by the Flask runtime. The backend orchestrator reads requirement sources, builds semantic context, calls embeddings and chat-completions APIs, synthesizes test cases, stores artifacts in output, and returns paths for preview/download.

Channel: Browser -> Local Runtime Control: Config-Driven Endpoints Generation: Semantic LLM First Retention: Cleanup on Download

Plain English: How The UI Talks To GHCP LLM

Think of the HTML page as a front desk, and the GHCP LLM as an expert analyst sitting in a secure back office. The front desk collects your request, passes it to the office system, and then shows you the final report.

  • Step 1: You choose what to generate in the UI. You provide a file, Confluence page, or Jira story IDs.
  • Step 2: The UI sends your request to the local Flask service. This happens through API calls like generate and preview/download routes.
  • Step 3: Flask passes it to the QE service layer. The service decides which connector to use (Document, Confluence, or Jira).
  • Step 4: Requirement text is extracted. The system converts your source into clean requirement content.
  • Step 5: Semantic preparation happens. The content is split into chunks, converted into embeddings, and ranked for relevance.
  • Step 6: GHCP-compatible LLM is called. The highest-value context is sent to the LLM chat endpoint to generate detailed test cases.
  • Step 7: Output files are created. Results are written as BDD feature files or Jira CSV test cases.
  • Step 8: UI shows and downloads output. You preview files in the UI and download what you need.
  • Step 9: Automatic cleanup. After download, generated output and temporary uploads are cleared based on runtime policy.

How This Works in VS Code

  • VS Code launches local runtime via [start.bat](start.bat).
  • Browser opens configured base URL from [app_config.properties](app_config.properties).
  • UI JavaScript calls backend routes provided by [web_app.py](web_app.py).
  • Backend orchestration executes in [core-logic/qe_service.py](core-logic/qe_service.py).
  • LLM calls are made from [core-logic/llm/ghcp_bridge_generator.py](core-logic/llm/ghcp_bridge_generator.py), not from frontend.

How Users Can Personalize These Files (Future Manual Updates)

  • Step 1: Open instructions/instructions.md. Add your team-specific runbook details such as naming standards, approval gates, security checks, and release rules.
  • Step 2: Update source flow specifics. For example, add Jira project keys, Confluence space conventions, and required metadata fields.
  • Step 3: Open skills/skills.md. Add or refine skills your QE team needs, such as API test generation, performance test generation, or compliance evidence mapping.
  • Step 4: Add quality rules per skill. Define expected outputs, minimum detail level, and non-functional checks for each skill.
  • Step 5: Keep changes versioned. Commit updates with a clear message (for example: "Update QE skill rules for payments domain").
  • Step 6: Validate after each change. Run one sample generation from UI and confirm outputs match your updated standards.
  • Step 7: Review quarterly. Treat both files as living standards so new projects, risks, and controls are continuously reflected.

Workflow Labels (Executive View)

  • Workflow 1: Intake - UI captures source selection, credentials (for Jira/Confluence), and output format.
  • Workflow 2: Retrieval - Backend connectors collect requirement payload from document/Jira/Confluence.
  • Workflow 3: Semantic Reasoning - Requirement is chunked, embedded, ranked, and sent to LLM with top context.
  • Workflow 4: Generation - Structured testcases are transformed into BDD feature files or Jira CSV.
  • Workflow 5: Delivery - UI previews/downloads generated artifacts via secured output endpoints.
  • Workflow 6: Hygiene - Runtime clears generated output and temp uploads after download completion.
